# 공통 문서 운영 기준

## 01. 목적과 관리 범위

이 가이드는 프로젝트의 공통 AI 작업 기준입니다. AI가 요청을 이해하고, 필요한 자료를 확인하고, 작업·검증·결과 정리를 진행하도록 돕습니다. 기획·디자인·프론트엔드·백엔드는 같은 문서 구조, 공용 스킬과 작성 형식을 사용합니다.

파트별 문서 내용·세부 절차·업무 스킬은 담당 PL이 관리합니다. 실제 저장소와 자료 위치, 도구 연동 방식은 추후 정리합니다.

## 02. 공통 구조

```text
각 파트 또는 실제 작업 저장소/
├─ AGENTS.md                 # AI 작업 시작점과 기본 작업 기준
├─ README.md                 # 파트 역할과 문서 안내
└─ docs/
   ├─ AGENTS.md              # 문서 작성·수정·검증 지침
   ├─ README.md              # 문서 구조 안내
   ├─ index.html             # 사람용 시작 페이지
   ├─ guides/                # 상세 기준과 작성 방법
   ├─ ai/                    # AI용 핵심 요약
   ├─ common-source/         # 참고 예시와 적용 조건 — 필요 시
   └─ workflow/
      ├─ AGENTS.md           # 요청별 문서·스킬 안내
      ├─ index.md            # 업무 안내 원본 — 필요 시
      ├─ index.html          # 사람용 업무 안내 — 필요 시
      ├─ skills/
      │  ├─ AGENTS.md        # 업무 스킬 선택·관리 지침
      │  └─ 스킬명/SKILL.md  # 파트별 업무 스킬 — 필요 시
      └─ scripts/            # 보조 도구 — 필요 시
```

현재는 각 파트에 기본 지침만 둡니다. 상세 문서·하위 폴더·업무 스킬은 실제 내용이 생길 때 담당 PL이 추가합니다. 같은 역할에는 같은 폴더 이름을 사용합니다.

## 03. 사람과 AI의 다른 시작점

- 사람은 전체 시작 페이지에서 파트 안내와 필요한 문서를 확인합니다. 파트의 HTML 문서가 없으면 README를 사용합니다.
- AI는 루트 AGENTS.md에서 요청을 확인한 뒤, 작업 대상에 적용되는 지침과 필요한 자료·요약·스킬을 선택합니다.
- docs/AGENTS.md는 문서 편집 지침입니다. workflow/AGENTS.md는 협의·작업·검증·기록에 필요한 문서와 스킬을 안내합니다.
- guides/에는 상세 기준과 방법을, ai/에는 필요한 핵심 요약을, workflow/에는 업무 절차와 기록 기준을 둡니다.
- 모든 문서와 스킬을 매번 읽지 않습니다. 같은 내용의 Markdown과 HTML도 중복해서 읽지 않습니다. 요약이 부족하거나 자료가 충돌하면 해당 원본을 확인합니다.

**요청에 필요한 문서만 읽도록 나눈 구조**

폴더와 지침을 계층으로 나누는 목적은 AI가 이번 요청에 필요한 문서를 선택하게 하는 것입니다. AGENTS.md의 문서 목록은 연결된 파일을 모두 읽으라는 목록이 아닙니다. 각 문서의 짧은 요약과 참고할 상황을 보고 필요한 문서만 선택하는 안내입니다.

루트 AGENTS.md는 요청에 맞는 파트를 안내합니다. 해당 파트의 AGENTS.md는 작업 종류에 맞는 하위 지침과 문서를 안내합니다. AI는 이 순서로 필요한 범위를 좁혀 읽고, 추가 근거가 필요할 때 관련 원본을 확인합니다. 작업 대상에 적용되는 상위·하위 지침과 선택한 스킬의 필수 지침은 유지합니다.

**컨텍스트 윈도우와 읽기 범위**

컨텍스트 윈도우는 AI가 현재 응답을 만들 때 함께 참고할 수 있는 정보의 범위입니다. 사용자 요청, 대화 내용, 지침, 읽어 온 문서 등이 이 범위에 포함됩니다. AI가 프로젝트의 모든 자료를 한 번에 참고할 수 있는 것은 아닙니다.

관련 없는 문서까지 전부 읽으면 이번 작업과 무관한 정보도 함께 다루게 됩니다. 필요한 기준을 선택해 읽도록 하면 작업에 집중할 수 있고 불필요한 읽기를 줄일 수 있습니다. 요약만으로 판단하기 어려운 사항은 원본을 확인합니다.

**AGENTS.md 작성 방법**

각 폴더의 AGENTS.md에는 폴더의 역할, 간단한 작업 지침, 문서별 한 줄 요약과 참고할 상황을 작성합니다. 긴 설명·상세 명세·코드 예시는 별도 문서에 두고 필요한 경우에만 읽도록 안내합니다.

| 문서 목록에 적을 항목 | 작성 방법 |
| --- | --- |
| 문서 | 필요한 파일을 찾을 수 있는 이름과 경로 |
| 짧은 요약 | 이 문서가 어떤 기준이나 정보를 제공하는지 한 줄로 설명 |
| 참고할 상황 | 어떤 요청이나 판단에서 이 문서가 필요한지 구체적으로 설명 |

예를 들어 정책 검토 문서는 정책의 누락이나 충돌을 검토할 때, HTML 템플릿 안내는 사람용 문서를 새로 작성할 때 참고하도록 적습니다. 모든 작업에 모든 문서를 먼저 읽도록 안내하지 않습니다.

**폴더와 지침 관리 방법**

- 문서가 늘어나면 업무나 주제별로 폴더를 나누고, 해당 폴더에 문서 목록과 간단한 지침을 둡니다. 내용이 적을 때부터 폴더를 잘게 나누지 않습니다.
- 상위 지침에는 공통 기준과 다음에 참고할 위치를, 하위 지침에는 해당 작업의 기준과 필요한 문서 요약을 둡니다. 상세 설명을 루트 AGENTS.md에 계속 추가하지 않습니다.
- 같은 규칙을 여러 폴더에 복사하지 않습니다. 공통 기준은 원본을 참조하고 하위 지침은 해당 영역에서 필요한 내용만 보완합니다.
- 문서를 추가·이동·수정하면 문서 목록의 경로·요약·참고할 상황도 함께 갱신합니다. 요약이 원본의 의미나 적용 조건을 바꾸지 않도록 확인합니다.
- AI 도구마다 지침을 발견하고 읽는 방식이 다를 수 있습니다. 폴더를 만들었다고 모든 지침이 자동 적용된다고 가정하지 않습니다. 실제 사용할 때 시작점과 작업 범위를 전달합니다.

## 04. 공통 문서와 업무 원본

| 구분 | 역할 |
| --- | --- |
| 공통 가이드 | AI의 작업 방법, 문서 구조, 공용 스킬과 작성 형식 |
| 기획서·계약·소스 | 기능·정책·합의·구현의 실제 근거 |
| 업무 기록 | 작업·질문·문제·결정·진행 상태와 검증 결과 |

향후 Redmine을 도입하면 지정된 업무 기록을 참고해 공통 기준에 따라 작업합니다. 기획 내용과 이슈 상세는 각 원본에서 관리하고, 공통 가이드에 별도 확정본으로 복제하지 않습니다. 등록·수정 요청과 권한이 있을 때만 외부 업무 기록을 변경합니다. 현재는 연동 설정이나 자동 등록 기능을 만들지 않습니다.

직접 작성하는 가이드와 안내는 Markdown을 원본으로 관리하고 HTML에 반영합니다. 기존 업무 원본의 승인 상태는 유지합니다. AI의 제안·검토·구현·검증 결과를 정책 확정이나 업무 승인으로 처리하지 않습니다.

## 05. 기본 작업 기준과 결과 정리

- 검토 요청은 원본을 읽고 의견을 제시합니다. 수정 요청은 지정한 범위에서 변경합니다. 계획·초안 작성을 실제 구현이나 외부 등록 권한으로 확대하지 않습니다.
- 작업을 재개할 때는 이전 결정·변경·검증 결과·미확인 사항·다음 작업부터 확인합니다. 실제 자료와 현재 상태를 기준으로 이어서 작업합니다.
- 없는 정책·API·일정·담당을 추측하지 않습니다. 자료가 충돌하면 근거와 영향을 설명하고, 판단이 필요한 부분과 독립적으로 진행할 수 있는 범위를 구분합니다.
- 결과에는 변경 내용·적용 근거·실제 검증 결과·미확인 사항·다음 작업을 정리합니다. 작은 작업은 결과 보고에 포함하며 별도 기록 양식을 강제하지 않습니다.
- 문서 검토·구현·실제 동작 검증은 구분합니다. 수행하지 못한 검증은 완료로 표시하지 않습니다.

파트 간 영향은 [협업 지침](../collaboration/AGENTS.md)에 따라 확인합니다. 실제 업무 기록이 정해지면 그 원본에 상세 내용을 남깁니다.

## 06. 업무 절차와 스킬

각 파트는 docs/workflow/skills/스킬명/SKILL.md에 반복 업무를 위한 스킬을 만들 수 있습니다. 종류·내용·추가·수정·사용 절차는 담당 PL이 관리합니다.

workflow/AGENTS.md는 요청별 문서와 스킬을 안내하고, skills/AGENTS.md는 스킬별 사용 조건을 정리합니다. 이번 작업에 필요한 스킬을 선택하고, 선택한 지침에서 요구하는 근거를 확인합니다. 단순 수정에 전체 명세·작업 기록·스킬 절차를 요구하지 않습니다.

공용 스킬은 공통 작업 방법과 작성 기준을 제공합니다. 파트별 업무 스킬은 각 파트의 상세 기준과 절차를 보완합니다. 스킬은 특정 AI 제품이나 자동 호출 기능에 의존하지 않는 Markdown 지침으로 작성합니다. 필요한 SKILL.md를 직접 읽어서도 사용할 수 있어야 합니다.

공용 업무 스킬은 기획·요구 검토 → 설계·작업 계획 → 작성·수정·검증 → 결과 검토·인수인계의 네 역할을 제공합니다. 필요한 단계에서 시작하고 모든 단계를 매번 실행하지 않습니다. [공용 업무 흐름](../collaboration/workflow.md)에서 요청별 선택과 받을 결과를 확인합니다.

기획 보완이 필요하면 [기획 보완 코멘트 — 사람·AI 공통 양식](../collaboration/planning-comments.md)으로 질문·반영 요청·작업 영향을 정리합니다. 파트별 상세 기준과 업무 스킬은 담당 PL이 관리합니다.

가이드·브리핑 작성 스킬은 [skills/guides/](../skills/guides/AGENTS.md)에, 실제 프로젝트의 기획 검토·설계·소스 작성·리뷰 스킬은 [skills/development/](../skills/development/AGENTS.md)에 구분합니다. 파트별 상세 기준과 업무 스킬은 담당 PL이 관리합니다.

## 07. HTML 형식과 문서 자원

- [공통 템플릿](../templates/index.html)의 header → main/section → footer 구성을 사용합니다. 문서 상단에는 종류·제목·설명을, 하단에는 문서명만 표시합니다.
- 주요 절은 번호 있는 h2를 사용합니다. common.js의 절 이동 메뉴와 별도 수동 목차를 중복해서 만들지 않습니다.
- 수기 가이드에 날짜·버전·Draft 표시를 일괄 추가하지 않습니다. 결정 일자·업무 상태·검증 환경은 필요한 기록 본문에서 관리합니다.
- 공통 CSS·JS는 assets/의 파일을 사용합니다. 템플릿을 복사할 때 파일 위치에 맞춰 상대 경로를 조정합니다. 저장소와 배포 위치를 가정해 새 연결을 만들지 않습니다.
- 파트 색상은 기획 핑크·디자인 그린·프론트엔드 블루·백엔드 옐로우로 통일합니다. data-part와 공통 색상 변수를 사용합니다.
- 링크는 목적이 드러나는 텍스트를 사용합니다. 코드의 문자·공백·줄바꿈과 식별자를 보존합니다. HTML의 개별 미정 항목은 badge-tbd를 사용합니다.
- 문서 변경 시 링크·구조·자원 경로·원본과 HTML의 내용 일치를 확인합니다. 화면을 바꾸면 가능한 범위에서 데스크톱·모바일 화면을 확인하고, 확인하지 못한 범위를 표시합니다.

## 08. 글쓰기와 공통 용어

한국어 문서에는 [공용 글쓰기 스킬](../skills/guides/korean-work-writing/SKILL.md)을 적용합니다. 제목은 내용을 바로 알 수 있게 쓰고, 안내 본문은 차분한 ‘합니다’체로 작성합니다. 문장을 다듬더라도 정책·책임·조건·수치·출처·승인 상태는 유지합니다.

| 용어 | 사용하는 의미 |
| --- | --- |
| 파트 | 기획·디자인·프론트엔드·백엔드의 업무 구분 |
| 사람용 시작 페이지 | 사람이 가이드와 문서를 찾는 HTML 페이지 |
| AI 작업 시작점 | 요청별 지침·자료·스킬을 안내하는 AGENTS.md |
| 문서 목록 | 문서와 참고할 상황을 정리한 안내 |
| 공용 스킬 | 여러 파트가 함께 사용하는 지침 |
| 공용 업무 스킬 | 요청 종류에 맞춰 공통 작업 방법과 결과 형식을 안내하는 지침 |
| 파트별 업무 스킬 | 담당 PL이 자기 파트의 상세 기준과 절차를 관리하는 지침 |
| 검토 | 내용·근거·차이·영향을 살펴보는 작업 |
| 검증 | 정한 방법으로 동작이나 결과를 직접 확인하는 작업 |
| 미정 | 결정이나 합의가 필요한 상태 |
| 미확인 | 자료나 실제 상태를 확인하지 못한 상태 |

공식 명칭, 파일명, 코드 식별자와 실제 인용은 보존합니다. 교정 예시에 있는 잘못된 표현을 현재 문서의 표현으로 사용하지 않습니다.
