# 문서 관리 기준

## 문서별 역할

- 루트 AGENTS.md: 공통 AI 작업 기준과 요청별 시작점
- 실제 파트 저장소의 AGENTS.md: 파트 역할, 문서 목록과 기본 작업 기준
- 이 저장소의 파트 폴더: 저장소 연결과 기본 구조 예시
- 파트 README.md: 파트 역할과 공통 작성 기준 안내
- docs/AGENTS.md: 문서 작성·수정·검증 지침
- docs/guides/: 상세 기준과 작성 방법
- docs/ai/: 필요한 핵심 요약
- docs/workflow/: 업무 절차·업무 스킬·기록 기준

기획서와 업무 기록은 각 원본에서 관리합니다. 공통 가이드에 기획 내용·이슈 상세·진행 상태를 별도 확정본으로 복제하지 않습니다.

## 공통 기준의 반영 절차

1. 팀원은 작업 중 발견한 규칙·스킬·검증 방법과 적용 근거를 파트 PL에게 전달하고 논의합니다.
2. 파트에만 필요한 내용은 해당 파트 PL이 파트 공통 저장소에 반영하거나 반영 방법을 안내합니다.
3. 여러 파트 또는 프로젝트 전체에 필요한 내용은 파트 PL과 공통 관리자가 적용 범위·관련 파트의 영향을 조율한 뒤 공통 저장소에 반영합니다.
4. 전체 공통으로 올리지 않는 내용도 파트에서 필요하면 해당 파트 저장소에 남겨 관리합니다.
5. 원본을 반영하면 관련 안내·링크·HTML 표현을 갱신합니다. 의견 제안, 기준 확정, 실제 반영과 검증 완료를 구분합니다.

공통 관리자는 파트 PL에게 전달받은 저장소와 시작점 주소를 README와 웹 시작 페이지에 반영합니다. 각 파트 PL은 자기 파트의 하네스·가이드·공통 기준을 최신 상태로 관리합니다. 개인 하네스의 변경을 다른 작업자에게 자동 적용되는 규칙으로 취급하지 않습니다.

## 기준과 확인 상태

| 상태 | 의미 |
| --- | --- |
| 확정 | 승인 근거와 적용 범위가 확인된 기준 |
| 현행 확인 | 특정 자료·소스·환경에서 직접 확인한 상태 |
| 제안 | 검토가 필요한 안 |
| 미정 | 결정이나 합의가 필요한 상태 |
| 미확인 | 자료나 실제 상태를 확인하지 못한 상태 |
| 대체됨 | 후속 기준으로 변경된 상태. 이전 이력과 후속 기준을 함께 보존 |

목표 기준과 현재 구현이 다르면 각각 기록합니다. 문서가 최근이라는 이유나 코드가 존재한다는 이유만으로 정책을 확정하지 않습니다.

## 수정 순서

1. 요청 범위와 관련 원본을 확인합니다.
2. 변경 이유·근거·적용 범위를 정리합니다.
3. 관련 파트와 문서에 미치는 영향을 확인합니다.
4. Markdown 원본을 수정하고 HTML·필요한 요약·문서 목록에 반영합니다.
5. 링크·구조·자원 경로·원본과 HTML의 내용 일치를 확인합니다.
6. 실제 검증 결과·미확인 사항·다음 작업을 정리합니다.

생성 자료는 지정된 원본과 갱신 방법을 따릅니다. 실제 업무 기록이 정해지면 그 원본에 상세 내용을 남깁니다.

## 하네스와 가이드 검증

문서 구조와 링크·기준의 일관성을 점검하고, 변경한 규칙과 관련된 대표 과제로 실제 행동을 확인합니다. 요청·기대 행동·실제 기록을 대조하고, 수정 후 영향받는 과제를 다시 검증합니다. 상세 방법과 기록 항목은 [하네스와 가이드 자체의 검증](ai-context.md#하네스와-가이드-자체의-검증) · [사람용 안내](ai-context.html#harness-validation)를 확인합니다.

## HTML 형식과 표현

[공통 문서 운영 기준](documentation.md), [HTML 템플릿](../templates/index.html), [공용 글쓰기 스킬](../skills/guides/korean-work-writing/SKILL.md)을 사용합니다. 제목과 본문의 용어를 통일하고 정책·책임·조건·수치·승인 상태를 보존합니다.

날짜·버전·Draft 표시는 수기 가이드에 일괄 추가하지 않습니다. 결정 일자·업무 상태·검증 환경은 필요한 기록 본문에서 관리합니다.

파트 색상은 [공통 색상 기준](part-colors.md)을 따릅니다. 공통 자원 변경은 사용하는 문서에 반영되지만, 템플릿 본문 변경이 기존 복사본에 자동 반영되지는 않습니다.
