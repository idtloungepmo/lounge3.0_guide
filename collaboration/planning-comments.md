# 기획 보완 코멘트 — 사람·AI 공통 양식

사람이 직접 작성하거나 AI에 요청할 때 같은 항목으로 기획 보완 내용을 정리합니다. 관련 원본·이전 결정·기존 코멘트에 이미 답이 있는지 먼저 확인합니다.

## 01. 작성 기준

- 한 코멘트에는 함께 결정할 주제 하나를 작성합니다. 질문이 서로 독립적이면 나누고, 긴 설계 검토는 필요한 업무 기록에서 다룹니다.
- 실제 확인한 내용과 결정할 질문을 구분합니다. 자료를 읽지 못한 상태를 기획 누락으로 단정하지 않습니다.
- 기획서에 어떤 조건·분기·상태·설명을 보완해야 하는지 구체적으로 요청합니다. 담당과 기한은 확인된 경우에만 지정합니다.
- 선택지와 기술 제안은 확정 정책과 구분합니다. 같은 질문이 논의 중이면 기존 코멘트나 이슈를 확인해 중복 등록을 피합니다.

## 02. 공통 양식

```text
[기획 보완 요청] <기능> — <결정할 항목>
대상: <화면·슬라이드·기획 항목과 확인 가능한 식별 정보>
현재 확인: <관련 원본에서 확인한 내용과 근거·확인 범위>
확인 요청: <실제 상황과 결정할 질문>
기획서 반영 요청: <추가·수정할 조건·분기·상태·설명>
작업 영향: <관련 파트와 진행 가능한 범위·보류할 범위>
협의 대상: <결정할 역할·확인된 담당 / 모르면 미정>
```

기존 결정이나 이슈 번호가 있으면 함께 적습니다. 작은 보완 요청은 목적에 필요한 항목만 사용합니다. ‘상세 기획 부탁드립니다’처럼 무엇을 결정해야 하는지 알 수 없는 문장 대신 실제 상황과 질문을 작성합니다.

## 03. 직접 작성과 AI 요청

사람이 직접 작성할 때는 대상과 근거를 확인하고 필요한 항목을 채웁니다. AI에 초안을 요청할 때는 대상·검토 범위·원하는 결과를 지정합니다.

```text
대상: <기획서·화면·슬라이드·기획 항목>
검토 범위: <기능·흐름과 이번에 확인할 사항>
기획·요구 검토 스킬과 공통 코멘트 양식으로 보완 코멘트 초안을 작성해줘.
관련 원본·이전 결정·기존 코멘트에서 먼저 답을 찾고 중복 질문은 제외해줘.
확인한 내용, 결정할 질문, 기획서 반영 요청과 작업 영향을 구분해줘.
이번 요청은 초안 작성까지야.
```

초안만 요청했다면 등록하지 않습니다. 등록을 요청한 경우 대상·범위·도구 지원·권한을 확인합니다. 위치 지정이 지원되면 해당 영역에 등록하고, 지원되지 않으면 본문에 확인된 대상 정보를 남깁니다. 대상과 범위가 이미 명확하게 승인된 작업에 반복적인 확인 절차를 추가하지 않습니다.

등록 성공은 실제 코멘트·이슈의 ID나 링크 등 반환 결과로 확인합니다. 도구나 권한이 없으면 초안과 필요한 확인 사항을 제공하며 등록 완료로 표시하지 않습니다. 현재는 특정 도구의 API·등록 위치·연동 설정을 정하지 않습니다.

## 04. 답변 이후 확인

- 초안·등록 성공·등록 실패 상태를 구분합니다. 실제 등록한 경우 확인된 코멘트나 이슈 식별 정보를 업무 원본에 남깁니다.
- 답변이 오면 결정 내용·근거·결정 주체·적용 범위를 확인합니다. 담당과 권한이 확인되지 않은 답변을 확정 정책으로 처리하지 않습니다.
- 기획서에 반영됐는지 확인하고, 미반영이면 구분합니다. 관련 작업의 진행 가능 범위·보류 범위·재개 조건을 갱신합니다.
- 질문 등록·정책 확정·기획서 반영·구현·검증 완료는 각각 구분합니다. 요청 없이 기존 코멘트나 이슈를 삭제·해결 처리하지 않습니다.

기획서와 향후 Redmine의 실제 기록은 각 원본에서 관리합니다. 이 가이드에는 양식과 작성 기준만 두고 실제 질문·답변·이슈 상세를 중복 관리하지 않습니다.
