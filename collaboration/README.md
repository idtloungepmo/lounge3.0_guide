# 파트 간 협업 절차

## 작업 흐름

1. **범위 확인:** 목표·대상 기능·플랫폼·이번 작업의 완료 조건을 정합니다.
2. **근거 확인:** 관련 파트의 지침과 필요한 기획·디자인·계약·소스를 읽습니다. 버전과 확인 범위를 남깁니다.
3. **차이 확인:** 확정 기준·현행 동작·제안·미정을 구분합니다.
4. **변경 영향 확인:** 아래 표로 관련 파트·계약·검수·일정 영향을 확인합니다.
5. **작업·검증:** 합의된 범위에서 진행하고 실제 변경과 검사 결과를 남깁니다.
6. **기준 갱신:** 변경된 원본·요약·관련 링크를 갱신하고, 남은 작업의 담당과 다음 행동을 기록합니다.

## 변경 시 함께 확인할 항목

| 변경 | 함께 확인할 내용 |
| --- | --- |
| 정책·요구사항 | 기획 근거 → 화면·문구·상태 → API·데이터 → 검수 조건 |
| IA·사용자 흐름 | 화면 ID·진입·복귀 → 디자인·라우트·권한 → WBS·검수 범위 |
| 디자인·토큰·공통 UI | 기획 의미 변화 → 코드·Storybook·영향 화면 → 환경별 검수 |
| API·데이터 | 업무 의미 → 소비 영역 → 오류·호환성 → 전환·검증 |
| Native·Bridge | 앱·웹 책임 → 지원 환경·전달 시점 → 실패·복귀 → 통합 검증 |
| 일정·범위 | 선행 결정·계약 → 의존 작업 → 완료 조건·담당·기준 일정 |

이 표는 확인할 관계를 안내하며 조직별 책임을 확정하지 않습니다.

## 다른 파트에 전달할 내용

요청·변경 이유 / 원본·버전·식별 ID / 확정·제안·미정 / 영향받는 화면·계약·소스 / 필요한 판단 / 담당·기한 또는 미정 / 검수 조건 / 실제 결과.

답변이 필요한 질문은 어떤 작업이 왜 영향을 받는지 명시합니다. 정책이 미정이라는 이유로 관련 없는 작업까지 모두 중단하지 않습니다. 일정·WBS를 바꾸는 결정은 해당 원본과 담당에게 연결합니다.
