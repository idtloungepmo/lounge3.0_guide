# 파트별 워크플로우 구성 안내

각 파트 PL은 프로젝트 공통 기준을 참고해 자기 파트의 워크플로우를 구성하고 관리합니다. 공통은 근거 확인·미정과 확정의 구분·실제 검증·결과 기록·파트 간 협의 기준을 제공하고, 작업 순서와 사용할 스킬은 각 파트가 정합니다.

## 01. 공통 기준을 바탕으로 구성

기획·디자인·프론트엔드·백엔드는 각자의 업무와 자료에 맞는 절차를 사용합니다. 파트 PL은 [공통 AI 작업 지침](../AGENTS.md)과 [공통 문서 운영 기준](../project/documentation.md)을 AI에 전달하고, 파트 업무·자료·작업 환경을 함께 설명해 워크플로우를 작성하도록 요청합니다.

파트 워크플로우에는 다음 내용을 업무에 필요한 만큼 정리합니다.

- 어떤 요청에서 시작하고, 어떤 자료·이전 결정을 확인하는지
- 사용할 스킬과 각 단계의 입력·결과·검증 방법
- 다른 파트에 확인하거나 전달할 내용과 결과를 남길 위치
- 작은 수정·작업 재개·미정 사항이 있을 때의 진행 방법

모든 파트에 같은 단계나 문서를 일괄 적용하지 않습니다. 범위가 명확한 작은 작업은 필요한 절차부터 시작합니다.

## 02. 맷 포코크 스킬 활용

[Matt Pocock의 원본 스킬](https://github.com/mattpocock/skills)을 활용해 파트에 필요한 작업 방법을 연결합니다. 요구 정리는 `grill-with-docs`, 명세·작업 분해는 `to-spec`·`to-tickets`, 코드 구현·검증·리뷰는 `implement`·`tdd`·`code-review` 등을 참고할 수 있습니다. 각 PL은 자기 파트에 맞는 스킬과 적용 범위를 선택합니다.

선택한 스킬의 실제 원문·하위 스킬·참고 파일과 사용할 AI 도구의 지원 범위를 확인합니다. 원본의 사용 기준 커밋이나 버전과 연결 위치는 파트에서 관리합니다. 스킬의 이슈 등록·커밋 등 실행 범위와 기록 위치는 프로젝트·파트의 작업 기준 및 이번 요청에 맞춥니다.

공통에 있는 기존 `lounge-*` 스킬은 구성 참고용으로 남깁니다. 파트의 실제 워크플로우와 사용할 스킬은 담당 PL이 관리하는 저장소에서 확인합니다. [스킬 선택 안내](../skills/development/AGENTS.md)에서 원본과 기존 참고본을 구분합니다.

## 03. 기존 프론트·백엔드 구성 참고

| 파트 | 기존 구성의 간단한 예시 | 안내 |
| --- | --- | --- |
| 프론트엔드 | 요구·명세 → 작업 분해·착수 판단 → 구현·검증·리뷰. API·앱 경계와 변경 영향도 필요한 작업에서 확인합니다. | [파트 저장소](https://github.com/minsukong/lounge-docs) |
| 백엔드 | 요구·정책 질문 → 설계·작업 계획 → 구현·검증 → 리뷰. API·데이터·외부 연동에 맞는 검증을 선택합니다. | [파트 안내](../backend/README.md) |

두 예시는 기존에 파트별 `lounge-*` 스킬과 업무 기준으로 정리한 흐름입니다. 다른 파트는 이를 참고해 자기 업무에 맞게 구성합니다. 상세 절차는 각 파트 자료에서 관리합니다. 백엔드 저장소 주소는 전달되면 [저장소 안내](../README.md#저장소-안내)를 갱신합니다.

## 04. PL의 AI 요청 예시

```text
프로젝트 공통: https://github.com/idtloungepmo/lounge3.0_guide
파트: <기획·디자인·프론트엔드·백엔드>
파트 저장소·자료: <실제 경로 또는 링크>
주요 업무·작업 환경: <대표 작업, 사용하는 자료·도구>
공유 기록 위치: <결정·작업·검증 결과를 남길 위치>

공통 AGENTS.md와 문서 운영 기준, 파트의 기존 지침을 확인하고
우리 파트에 맞는 워크플로우 초안을 작성해줘.
맷 포코크 원본 스킬에서 필요한 것을 선택하고 연결 방법을 설명해줘.
요청별 시작점, 입력과 결과, 검증, 파트 간 전달과 기록 방법을 정리해줘.
기존 프론트·백엔드 흐름은 참고하되 우리 업무에 필요한 절차로 구성해줘.
이번 요청은 초안 작성까지야.
```

공통 링크만으로 자료를 읽었다고 가정하지 않습니다. AI가 실제로 접근한 지침과 확인하지 못한 자료를 구분하고, 원격 접근이 어려우면 내려받은 공통 가이드의 실제 위치를 전달합니다.

## 05. 실제 업무에 적용하고 보완

PL은 작성한 흐름을 검토하고 작은 실제 업무에 적용해 자료 확인 → 작업 → 검증 → 결과 기록이 이어지는지 확인합니다. 실제 사용하는 워크플로우와 요청별 스킬 안내는 파트 저장소의 AGENTS.md와 사람용 시작점에서 연결합니다. 작업자는 개인 AI·하네스를 사용하면서 프로젝트 공통과 파트 공통을 함께 확인합니다.

사용 중 발견한 개선 사항은 파트 PL과 논의합니다. 파트에서만 필요한 내용은 파트 공통에 반영하고, 여러 파트에 필요한 내용은 [공통 반영 절차](../project/maintenance.md#공통-기준의-반영-절차)에 따라 조율합니다.

결과에는 변경 내용·근거·실제 검증 결과·미확인 사항·다음 작업을 작업 규모에 맞춰 남깁니다. 기획서·업무 기록은 해당 원본을 유지하며 공통 가이드에 이슈 상세를 복제하지 않습니다. 기획 보완이 필요하면 [사람·AI 공통 코멘트 양식](planning-comments.md)을 사용합니다.
