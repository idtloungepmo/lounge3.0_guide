# 작성·수정·검증

## 역할과 공통 기준

이 스킬은 실제 프로젝트의 기획·설계·소스 작업에 사용하는 공통 방법입니다. 실제 프로젝트의 문서·디자인·소스를 변경할 때 선택합니다. [공통 AI 작업 지침](../../../AGENTS.md)을 따르고, 파트별 상세 기준·업무 스킬은 필요한 경우에만 추가로 확인합니다.

공통 가이드·브리핑 자체를 작성하거나 다듬는 작업은 [가이드 작성 스킬](../../guides/AGENTS.md)을 사용합니다.

## 확인할 입력

- 작업 대상·허용 범위·근거·완료 조건을 확인합니다. 계획이 이미 있으면 필요한 부분만 읽습니다.
- 작업 대상에 적용되는 지침과 기존 원본·설정·현재 상태를 확인합니다. 필요한 파트 기준과 스킬만 선택합니다.
- 필수 조건이 빠졌으면 영향받는 범위와 독립적으로 진행할 수 있는 작업을 구분합니다. 작은 수정에 별도 기획 검토·설계 절차를 추가하지 않습니다.

## 작업 방법

1. 현재 상태와 기존 사용자 변경을 확인하고, 요청과 관련된 범위만 변경합니다.
2. 기존 구성과 공통 자원을 먼저 확인합니다. 문서·디자인·코드의 실제 원본과 식별자를 보존합니다.
3. 한국어 문서는 [공용 글쓰기 스킬](../../guides/korean-work-writing/SKILL.md)을 적용합니다. 가이드의 Markdown을 수정하면 대응 HTML과 필요한 문서 목록도 맞춥니다.
4. 작업 유형에 맞는 검증을 수행합니다. 문서는 내용·링크·표현, 디자인은 필요한 상태·환경, 코드는 실제 검사·테스트 등 관련 기준을 따릅니다. 범위 밖의 일괄 개편을 추가하지 않습니다.
5. 검증 실패를 확인하면 원인과 관련 범위를 조사해 수정·재검증합니다. 수행하지 못한 검증과 정책·계약 미정은 결과에 남깁니다.
6. 필요한 기록은 지정된 원본을 사용합니다. 요청하지 않은 등록·상태 변경·배포를 완료 절차로 자동 추가하지 않습니다.

## 받을 결과

변경 내용·대상 / 적용 근거 / 실제 검증 방법·환경·결과 / 미확인·미실행 항목 / 완료 조건 충족 여부 / 다음 작업을 정리합니다. 문서 작성·디자인 확인·구현·실제 연동 검증을 구분합니다.


## 다음 작업과 기록

필요한 단계에서 시작합니다. 모든 스킬을 순서대로 실행하지 않습니다. 실제 결정·작업·이슈 상세는 지정된 원본에서 관리하고, 공통 가이드에는 복제하지 않습니다. 작업을 재개할 때는 이전 결과·미확인 사항·다음 작업부터 확인합니다.
